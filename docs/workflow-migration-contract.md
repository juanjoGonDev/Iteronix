# Workflow application migration contract

Phase 0 preserves the working workflow application while making its state portable and ready for later graph and governance work. This contract is the migration decision record; it does not introduce Phase 1 graph semantics, desktop delivery, plugins, or a new execution engine.

## Operating rules

- The PostgreSQL `app_state` row named `application` is canonical. A read falls back to the legacy `workspace` row only when `application` is absent; the next successful write creates or updates only `application` with optimistic revision control.
- Full application exports use schema version `1`, SHA-256 integrity checks over canonical JSON, runtime validation, and plaintext-secret redaction. Provider environment references and external API-key hashes remain portable metadata; plaintext credentials never do.
- Unknown schemas, malformed untrusted payloads, and checksum mismatches are rejected before persistence. Imports normalize legacy `workspace` envelopes and legacy `workspace` asset scope to `global`.
- The revisioned single-row store rejects conflicting writes; it does not retain a restorable revision history. Before a production migration, create and verify a redacted full-application export or database backup. Roll back by restoring that verified backup/export through the validated import path. Imports do not mutate stored state until the caller persists the validated result.

## Database and import versioning

The database state and the application export are independently versioned. PostgreSQL revision protects concurrent writes; export `schemaVersion` controls import compatibility. A future version must add: source/target mapping, forward upgrader, explicit backward compatibility window, rollback procedure, loss assessment, and fixture evidence before it can be accepted.

## Verification checklist

- [x] Legacy `workspace` envelope imports into canonical application state.
- [x] Legacy `workspace` asset scope imports as `global`.
- [x] Definitions, versions, assets/usages, executions, revoked API-key hashes, and provider references survive import, save, and reload.
- [x] Plaintext provider secrets are redacted from export and persistence.
- [x] Unknown schema, checksum mismatch, and malformed payload receive typed errors before persistence, including incomplete workflow definitions, versions, assets, usages, and executions.

## Excluded implementation surfaces

This phase does not add API endpoints for bulk transfer, React Flow graph contracts, lifecycle governance, plugins, Electron, or Playwright tooling. Existing Puppeteer browser validators remain baseline checks. New UI/API coverage must follow the approved Playwright policy in `AGENTS.md` when that later work begins.
